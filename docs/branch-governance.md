## 当前长期分支

- `master`：最终稳定发布分支，通过发布快照方式同步当前可验收项目版本。
- `feature`：课程协作和集成过程分支，保留用于展示开发、PR、测试和集成历史。

课程验收结束前不建议删除 `feature`。如果还需要补充小修复，先从 `feature` 新建 `fix/*`、`docs/*` 或 `test/*` 分支，合入 `feature` 并验证后，再按发布快照方式同步到 `master`。

## 需要单独处理的分支

### `origin/test`

状态：测试内容已通过 PR #10 迁移到 `feature`。

说明：该分支新增了后端测试，但同时改动了当前 `feature` 中的部分业务代码。团队没有直接 merge，而是只迁移可用测试代码和必要测试依赖，避免回退现有能力系统、控制器和玩家逻辑。

后续处理方式：

- 课程验收前保留该远程分支作为测试开发过程证据。
- 验收结束后再统一清理。

### `origin/master`

状态：通过发布快照 PR 承载当前稳定验收版本。

说明：最初尝试普通 `feature -> master` merge 时，由于 `master` 是旧模板结构、`feature` 是前后端分离项目结构，冲突范围较大。因此关闭 PR #13，改用 `release/* -> master` 发布快照方式完成集成。后续稳定版本继续沿用该方式同步到 `master`。

后续处理方式：

- `master` 作为最终验收版本，不直接开发。
- 如需补充修复，先在 `feature` 上完成并验证，再通过发布快照 PR 同步到 `master`。

## 新分支命名

- 功能：`feat/具体功能`
- 修复：`fix/具体问题`
- 测试：`test/测试范围`
- 文档：`docs/文档范围`

不再新增裸名长期分支，例如 `database`、`test`、`github-actions-ci`。
